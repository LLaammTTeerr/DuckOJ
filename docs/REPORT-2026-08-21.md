## Afternoon (14:00 → 16:40)

### Organizations are manageable over HTTP

`POST /orgs`, `PATCH /orgs/:slug`, `GET /orgs/:slug/members`. They had a full
permission model — owner/admin/member, join requests — and no write surface at
all. Membership *mutation* stays out: it needs the join-request state machine,
and half-implementing that is worse than not starting.

Slugs are mutable, because nothing references one — `problem_orgs`,
`org_members` and `org_join_requests` all key on `organizations.id`. A rename
breaks a stale bookmark, which 404s honestly. A problem code is a permanent
public citation; an org slug is a display handle.

### Submission source is viewable, under your four rules

Own always · admin all · author/curator per problem · AC-holders when the
problem enables it, via a new `source_access` flag defaulting to `private`.

The thing worth knowing: *"a curator may view their problem's submissions"*
widens **submission visibility itself**, not just a field on it. A curator who
could read the source but got a 404 on the submission would be incoherent.

That made the risk concrete — Phase 3b had extracted one predicate in two
forms so the list and the single read cannot disagree, and now both had to
widen identically or the failure would be a leak. They did: the agreement test
survived **byte-identical**, and mutating only the SQL form was caught by the
agreement property alone, with no test written for that case.

### A serious bug in my own morning fix

I added `--force-recreate` to `compose-up.sh` for `api`, `judged`, `caddy` and
`judge`, and **missed `migrate`** — the one step where reuse is silent.

The migrate container was **11 hours older than its image**. It re-ran
yesterday's migrations, found nothing new, exited 0, and the script printed
`Stack is up`. Migration 0007 never applied. First symptom was a 500 from
`GET /submissions` **with all 493 tests green**, because the tests use
Testcontainers, which builds the schema from migration files directly and
structurally cannot see this.

A stale `dist/` makes one mutation check lie. A stale image serves old code
that still works. A stale SDK hides one field. A stale migrate container
**corrupts the ground truth** — every check downstream then measures a database
that does not match the code, and the script whose purpose is preventing that
reports success while doing it.

Fixed, and the whole path re-verified end to end afterwards: create → upload →
attach → publish → submit → `AC 10/10`, then uncompilable source → `CE` from a
real judge. All 14 steps.
