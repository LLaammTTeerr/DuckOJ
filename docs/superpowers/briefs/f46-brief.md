# F-46 — Pascal and Java, because a province teaches them

## Why this slot

F-39 gave this judge five languages and proved the whole mechanism works:
`languages`, `language_driver_keys`, the executor allow-list in
`docker-compose.yml`, D154's per-language time multiplier and memory addend,
the picker, the drafts, the limits shown beside the language.

It stopped where the image stopped. C++ and Python needed no new toolchain;
**Pascal and Java need one**, so they were named as a gap and left.

They are not an afterthought for the audience this system is for. Vietnamese
provincial informatics teaching has a long Pascal tradition — a generation of
teachers learned and still teach it, and school-level rounds continue to
accept it. Java is widely taught in upper secondary. A judge that cannot run
either is a judge some schools in the province cannot use.

## Scope

### 1. The toolchain, in the image

Add Free Pascal and a JDK to `judge/Dockerfile`. Keep the image lean: prefer
the distribution's own packages, install no recommended extras, and say in the
report what each one costs in image size — this image ships to a province's
own hardware and one of them may be running it on modest kit.

`judge/judge.yml` carries a `runtime:` block whose comment says it was
generated by `dmoj-autoconf -V` inside the image, and warns that a stale path
here degenerates into a `KeyError` deep inside judge-server rather than a
clear "executor not found". **Regenerate it properly**; do not hand-edit paths
you guessed.

### 2. The executor allow-list

`--only-executors` in `docker-compose.yml` is the flag that kept this judge at
one language for two weeks (F-39). It appears on **both** judge services.
Widen it, and keep the comment there honest about what the list now is.

The list must stay a superset of the `executor_key`s in
`language_driver_keys`. Verify the executor names against what the image's own
self-test reports — **not** against what you expect them to be. F-39's brief
guessed `C17` and there is no such executor; the agent that checked found `C`
and `C11` instead, and named the row for what it actually compiles.

### 3. The language rows and their limits (D154)

A migration (**next number is 0046** — check the journal; D133 exists because
0025 was skipped forever), idempotent by key, in the shape 0042 established.

The multipliers are the interesting part and must be **measured on this
image**, the way D154 measured Python at 110× and CPython's 15 MB floor:

- Pascal compiles to native code — is a multiplier warranted at all?
- Java's cost is not proportional the way an interpreter's is: JVM **startup**
  is a fixed toll paid once per run, and its heap floor is large. D154 already
  decided that a proportional cost is a multiplier and a fixed cost is an
  addend. Decide which Java is, argue it, and record it. If the honest answer
  is that Java needs both, say so — the schema already has both columns.
- Whatever you choose, remember the ceiling: the DB refuses below 100 % or
  above 1000 % (D159), and a generous multiplier is judge time a province with
  one judge container does not have.

Record the ruling as **D169** (unspent).

### 4. The rest of the path

The editor mode for each language, the extension used for download, the
statement of limits beside the picker — all of this already exists for five
languages and should simply extend. Where it does not, that is a finding worth
reporting, because it means F-39 hardcoded something.

## Building images — the one exception to the usual rule

You normally may not build images. For this slot you may, under three
conditions, because a toolchain change cannot be verified any other way:

1. **One build at a time**, under `nice -n 19`, and **never while another
   suite runs**. This host reached 93 °C twice today; a judge image build is
   among the hottest things on it.
2. **Build to a throwaway tag** — `localhost/duckoj-judge:f46-probe` or
   similar. **Never** tag `duckoj_judge:latest`, which is what the live
   container runs.
3. **Never recreate, stop or restart a container.** You may `podman run --rm`
   your probe image to run `dmoj-autoconf -V` and to time a program. The live
   `duckoj_judge_1` is not yours to touch.

The controller builds and deploys the real image. Your report must say exactly
what to verify after that deploy, in the order to verify it.
