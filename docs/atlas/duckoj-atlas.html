Part I

The judge

Accounts and access

  • A school judge decides who may sign up. Registration is a two-rung policy and the default is closed: pupils arrive because a teacher made their accounts, and a visitor is told so in their own language rather than meeting a form that refuses them D200 · D201
  • Sign in, Vietnamese by default, English one click away D18
  • Optional TOTP two-factor, with recovery codes and an admin reset for a lost authenticator D39
  • Password reset by mail; changing a password kills every reset link in flight D141
  • On a stack with no mail relay the reset refuses with 503 instead of claiming it sent one — raised before the rate limiter and before the account lookup, so it stays uniform in timing as well as in wording and still reveals nothing about who has an account D155 · D26
  • Rate limits on login and registration, tuned so a student cannot lock themselves out D16 · D26
  • A teacher types nguyen and finds Nguyễn: names are searched through an accent-folded column, because a search that demands the reader produce the diacritics is useless to the people this is built for. Wired into the roster, the team form and the participant picker D185
  • Bulk student accounts with a forced first-login password change — no token is minted or honoured until it is done D61 · D102 · D140
  • A username is an identifier; a display name is a child. How much of a person is public is a deployment policy with three settings, and the protective one is what an operator gets by doing nothing: a stranger sees handles and ratings, a reader with standing in a school sees names. Before it, a stranger could walk contest standings to usernames to profiles and collect 264 of 481 real names without an account D197 · D198
  • The pupil directory is not a public download. Listing accounts needs an actor, and the walk — a request carrying a cursor — is metered per signed-in user, never per address, because thirty pupils behind one school's connection must not lock each other out mid-contest. An individual profile stays public, as a judge's profiles should be D188
  • Personal access tokens with explicit scopes; CSRF origin checks on every write D82
  • Organisations imported from a spreadsheet (org:import), contests restricted to them D56
  • A public school shows a page, not a download. Its roster stays readable without signing in — that is what "public" was chosen to mean — but a stranger gets one page, no cursor and no search, because a prefix search would walk the roster just as surely. Members and admins read it all, unmetered, since a five-thousand-pupil roster is two hundred presses of "load more" D191

Judging

  • The DMOJ sandbox, driven by a judged service that owns batching, dataset-aware point ceilings, attempt fencing and targeted cancellation D29
  • Horizontal scaling: judge:node add plus the compose scale profile. One judge grades ≈35 submissions/min
  • Per-user submission metering so one student cannot starve a contest D80
  • Live verdict feed with a deadline — if the socket goes quiet the page proves itself by polling D152 · D144
  • Seven languages: C++20, C++17, C++14, C11, Python 3, Pascal and Java 17 — Pascal because provincial informatics teaching in Vietnam has taught it for a generation and school rounds still accept it. Dispatched through a key→executor mapping table, so judge-server's names never become ours
  • Per-language time and memory allowances, because an interpreter is not a compiler. Time is a whole-percent multiplier, memory an addend — and the limit a student is shown is the limit the judge enforces D154
  • Every multiplier is measured on this judge, not copied from another. Python: 110× on a tight loop, a 15 MB interpreter floor → 300 % and +32 MB. Pascal: 1.05× on a sieve and a floor of 204 KB, below C++'s — so 200 % and no memory addend, because an addend would invent a cost
  • Java inverts the model and the decision says so: its time cost is a fixed 55 ms of JVM startup rather than a proportional factor, and its memory cost is proportional — the garbage collector wants 1.57× the live data. The schema offers a multiplier for time and an addend for memory, the wrong instrument in both directions, so both were sized against the limits setters actually author here D170
  • A setter can override either number per problem, or refuse a language outright — which answers 404, not a zero limit, because a refusal presented as a TLE teaches a student their correct program was too slow
  • The database refuses a multiplier below 100 % or above 1000 %, so an operator's typed 0 cannot silently turn a whole language into an instant TLE D159
  • A submission no connected judge can grade now says "waiting for a judge that can run this language" instead of sitting at queued forever D160 · D68
  • An executor the judge announces but the mapping does not know is dropped, never guessed. It used to be lowercased into a plausible-looking key, which is the one thing the mapping table exists to prevent — and it silently queued every Pascal submission until the service was restarted D172 · D173

Part II

The problem preparation pipeline

One command, prepare:problem, carries a problem from a directory on disk to a graded problem on the site. It refuses to publish anything it could not verify — and it never reports a check it did not run as a check that passed.

Two layouts, detected automatically

  • problem.xml means a Codeforces Polygon package; problem.json means the authoring-skills layout. A directory carrying both is read as Polygon
  • The package built from a Polygon directory has the same content hash as polygon:import + package:build produce — one artefact, one hash, one thing that gets graded
  • Statements must be Markdown: either statement.md with an ## English section, or statement.vi.md + statement.en.md

Stress testing a doubtful solution

  • Model against brute force over generated cases: <gen> <seed> writes one case to stdout
  • The two are compared through the problem's own checker, so a problem with several correct answers is not falsely reported broken
  • A brute force that crashes is a refusal, not a counterexample — the oracle has to be right

What the gate checks

MarkCheckWhat it proves
[x]statementVietnamese and English are both present
[x]manifestThe package describes itself completely
[x]testsEvery test has a non-empty answer
[x]limitsTime and memory limits are stated and sane
[x]flagsNo unresolved HIGH statement ambiguity — the one blocking flag
[x]checkerThe checker compiles
[x]validatorIt accepts every test the package ships
[x]modelThe model solution reproduces every answer through the real checker, inside the limits
[x]matrixEvery @expect group=VERDICT a solution declares is the verdict it actually gets

A skipped check is never a soft pass. [ ] names what was not run, so "the model solution was never checked" can never be misread as "the model solution agreed". [!] fails the gate. Exit codes: 0 ready, 1 the gate found something, 2 the request was refused outright. TLE here is wall-clock at 2× the limit — this is a local gate over your own code, not the grading sandbox; under an address-space limit a declared ML is satisfied by an observed RE. No testlib, no checker: the tool refuses with the fix in the message.

Packaging and publishing

# build the package offline and print its hash
prepare:problem package <dir> --out <pkg> --archive problem.tar.zst

# gate, build, create-or-patch, upload, attach a revision, publish
prepare:problem publish <dir> --publish --visibility public

A failing gate stops before anything reaches the server. Re-running is safe: unchanged content hashes the same and attaches no new revision, while the statement, tags and difficulty are patched every time. Tags and difficulty are looked up from meta.json or tags.json beside the problem, then from an ancestor — under both the problem code and the directory name. An editorial.md travels with the same run. The token needs problems:write, problems:publish and packages:write, and nothing more.

The whole path

  1. Author the directory: tests, solutions annotated with @tag and @expect, flags
  2. Add the statement in both languages
  3. Run the gate until it says READY
  4. Stress-test the model solution if it is still in doubt
  5. Publish. The problem is live, graded against the package whose hash you printed in step 3

Agents take the same path without a shell: problems_draft_create, problems_draft_put_file, problems_draft_build over MCP call the same library the CLI does — no subprocess, same gate, same refusals.
